# תרגיל 11 - Analiza Chat: שרת צ'אט בזמן אמת עם Socket.io 💬

עד עכשיו השרת שלנו רק **ענה** לבקשות: הלקוח שואל, השרת עונה, והחיבור נסגר. בצ'אט זה לא מספיק: כשמיכל שולחת הודעה, השרת צריך **לדחוף** אותה לדנה בלי שדנה ביקשה כלום. בשביל זה יש WebSocket, חיבור שנשאר פתוח ושני הצדדים יכולים לשלוח בו הודעות מתי שהם רוצים. הספרייה **Socket.io** עוטפת את WebSocket ונותנת לנו אירועים עם שמות: `socket.emit("שם", data)` בצד אחד, ו-`socket.on("שם", (data) => ...)` בצד השני.

**מה בונים:** את השרת של אפליקציית צ'אט. **הלקוח כבר מוכן** (HTML, CSS ו-JS בתיקייה `public/`). הוא יודע להתחבר, לשלוח הודעות ולהציג אותן, אבל בלי שרת שום דבר לא עובד. אתן כותבות רק את `server.js`, עם Express ו-Socket.io.

**זמן משוער:** שעה וחצי עד שעתיים.

## איך מתחילות

1. לוחצות למעלה על **Use this template** ← **Create a new repository**, ויוצרות ריפו משלכן.
2. עושות `git clone` לריפו החדש ופותחות אותו ב-VS Code.
3. בטרמינל מריצות פעם אחת: `npm install`. צריך Node בגרסה 20 ומעלה, ובודקות עם `node -v`. `express` ו-`socket.io` כבר מופיעים ב-`package.json`.
4. כותבות את השרת ב-`server.js`. את הקבצים ב-`public/` לא צריך לשנות, אבל כדאי לקרוא את `public/client.js` ולראות אילו אירועים הלקוח שולח ולאילו הוא מאזין.
5. מריצות את השרת: `npm start`, או `npm run dev` כדי שיופעל מחדש בכל שמירה. עוצרות עם `Ctrl + C`.
6. פותחות בדפדפן את **http://localhost:3000** בשתי לשוניות (או בשני דפדפנים), נכנסות עם שני כינויים שונים ומדברות עם עצמכן 🙂

> ⚠️ את הדף פותחים מהשרת שלכן (`http://localhost:3000`), **לא** עם Live Server. הקובץ `/socket.io/socket.io.js` קיים רק כשהשרת שלכן רץ.
>
> 💡 רוצות לדבר עם חברה? אם אתן באותה רשת Wi-Fi, היא יכולה לפתוח `http://<כתובת ה-IP שלך>:3000`. את כתובת ה-IP מוצאים עם `ipconfig` ב-Windows.

## חוזה האירועים

הלקוח והשרת צריכים להסכים על **שמות האירועים** ועל **מה נשלח בהם**. זה החוזה, והלקוח המוכן והטסטים בנויים עליו בדיוק:

**מהלקוח לשרת** (השרת מאזין עם `socket.on`):

| אירוע | מה נשלח | מתי |
|---|---|---|
| `join` | `nickname` (מחרוזת), ו-`callback` (פונקציה) | לחיצה על "כניסה לצ'אט" |
| `chat:message` | `text` (מחרוזת) | שליחת הודעה |
| `typing` | כלום | בזמן הקלדה בתיבת ההודעה |

**מהשרת ללקוח** (השרת שולח עם `io.emit` או `socket.broadcast.emit`):

| אירוע | מה נשלח | למי |
|---|---|---|
| `system` | מחרוזת, למשל `"Dana הצטרפה לצ'אט"` | לכולן |
| `users` | מערך של כל הכינויים המחוברים, למשל `["Dana", "Michal"]` | לכולן |
| `chat:message` | אובייקט `{ nickname, text, time }` | לכולן, כולל השולחת |
| `typing` | הכינוי של מי שמקלידה, למשל `"Dana"` | לכולן **חוץ** מהשולחת |

### מי מקבלת? שלוש דרכים לשלוח

```js
socket.emit("event", data);           // רק ללקוח הזה
io.emit("event", data);               // לכל הלקוחות המחוברים
socket.broadcast.emit("event", data); // לכל הלקוחות חוץ מהלקוח הזה
```

## שלבים

### שלב 1: שרת Express ו-Socket.io על אותו שרת

Socket.io צריך לשבת על אותו שרת `http` ש-Express משתמש בו:

1. יוצרות אפליקציית `express` שמגישה את התיקייה `public` עם `express.static`. אחר כך `GET /` מחזיר את `index.html`.
2. יוצרות שרת `http` מהאפליקציה: `http.createServer(app)`.
3. יוצרות שרת Socket.io על אותו שרת: `new Server(server)`, כאשר `Server` מגיע מ-`require("socket.io")`.
4. מאזינות לפורט `3000` עם `server.listen(3000)`.
5. מאזינות לחיבורים עם `io.on("connection", (socket) => { ... })`, ובכל חיבור מדפיסות:
   ```
   User connected: <socket.id>
   ```

רמז: אם תכתבו `app.listen(3000)` ו-`new Server(...)` על שרת **אחר**, הדף ייטען אבל הלקוח לא יצליח להתחבר. בדיקה מהירה: `http://localhost:3000/socket.io/socket.io.js` צריך להציג קובץ JS ארוך.

✔ בדיקה בדפדפן: אחרי השלב הזה מופיע בדף "מחוברת לשרת ✓", ובטרמינל של השרת מודפס `User connected: ...`.

### שלב 2: הצטרפות עם כינוי (`join`)

הלקוח שולח `join` עם הכינוי **ועם פונקציה** (callback). זה נקרא **acknowledgement**: השרת קורא לפונקציה, והתשובה חוזרת ללקוח ששלח:

```js
socket.on("join", (nickname, callback) => {
  // ...
  callback({ ok: true });
});
```

1. מורידות רווחים מהכינוי (`trim`).
2. כינוי ריק עונה `callback({ ok: false, error: "חובה להזין כינוי" })`.
3. כינוי שכבר תפוס על ידי מישהי מחוברת עונה `callback({ ok: false, error: "הכינוי כבר תפוס" })`.
4. אחרת:
   - שומרות את הכינוי על ה-socket, עם `socket.data.nickname = nickname`. ככה בכל אירוע אחר של אותו socket יודעים מי היא.
   - שומרות את הכינוי ברשימת המחוברות (מערך).
   - עונות `callback({ ok: true })`.
   - שולחות **לכולן** אירוע `system` עם הטקסט `"<nickname> הצטרפה לצ'אט"`, למשל `"Dana הצטרפה לצ'אט"`.
   - שולחות **לכולן** אירוע `users` עם המערך של כל הכינויים.

רמז: הצטרפות שנדחתה לא מוסיפה אף אחת לרשימה ולא שולחת הודעת `system`.

✔ בדיקה בדפדפן: נכנסות כ-Dana בלשונית אחת. בלשונית שנייה מנסות שוב "Dana" (שגיאה), ואחר כך "Michal". בשתי הלשוניות רואים את שתיהן ברשימה בצד.

### שלב 3: הודעות צ'אט (`chat:message`)

כשמגיע `chat:message` עם `text`:

1. אם ה-socket לא עשה `join` (אין לו `socket.data.nickname`), מתעלמות.
2. מורידות רווחים מהטקסט. טקסט ריק לא נשלח.
3. שולחות **לכולן, כולל השולחת**, אירוע `chat:message` עם אובייקט:
   ```js
   { nickname: "Dana", text: "Hi everyone!", time: "2026-11-08T12:00:00.000Z" }
   ```
   את `time` יוצרות עם `new Date().toISOString()`.

רמז: גם השולחת צריכה לקבל את ההודעה בחזרה, כי ככה היא מופיעה אצלה על המסך.

### שלב 4: "מקלידה..." (`typing`)

כשמגיע `typing` מ-socket שעשה `join`, שולחות לכל **האחרות** אירוע `typing` עם הכינוי שלה. השולחת לא צריכה לראות "Dana מקלידה..." על עצמה, לכן משתמשות ב-`socket.broadcast.emit`.

### שלב 5: יציאה (`disconnect`)

כשלשונית נסגרת, Socket.io מפעיל בשרת את האירוע `disconnect` על אותו socket:

1. אם ל-socket אין כינוי (הוא אף פעם לא עשה `join`), לא עושות כלום.
2. אחרת מוציאות את הכינוי מרשימת המחוברות, כדי שהוא יתפנה לשימוש חוזר.
3. שולחות לכולן `system` עם `"<nickname> עזבה את הצ'אט"`.
4. שולחות לכולן `users` עם הרשימה המעודכנת.

✔ בדיקה בדפדפן: סוגרות לשונית אחת, ובלשונית השנייה מופיע "Michal עזבה את הצ'אט" והרשימה בצד מתעדכנת.

## בונוס ⭐: היסטוריית הודעות

מי שנכנסת עכשיו לא רואה מה נכתב לפניה. הוסיפו endpoint רגיל של Express:

- **Route:** `GET /api/messages`
- **Response:** מערך JSON של **20 ההודעות האחרונות** (באותו מבנה `{ nickname, text, time }`), מהישנה לחדשה.

רמז: שומרות כל הודעה שנשלחת במערך, ומחזירות `messages.slice(-20)`. הלקוח המוכן כבר קורא ל-`/api/messages` אחרי ההצטרפות ומציג את ההודעות הקודמות מעל הקו "הודעות קודמות".
